# 输出日志功能优化：从提示词复制到可审计报告（v8.4.2）

- 时间：2026-08-07 16:28（Asia/Shanghai）
- 用户方向：基于最新研究，优化“输出日志”的功能。
- 实现文件：`index.html`
- 验证脚本：`validate/validate_output_log.mjs`
- 性质：输出、交互和证据表达升级；v8.4 筛查模型、系数及风险阈值均未改变。

## 一、依据与目标

### 1. 最新内部研究

结构储备研究 `experiment_20260807_1533.md` 显示：

- 4 日结构共识分半可靠性仅 Hall ρ=0.298、Weinstock ρ=0.170；6 日分别为 0.445、0.125。
- 结构共识与 OGTT 的 Spearman 为 0.022，控制常规指标后的偏相关为 −0.007。
- 加入结构共识未改善 Hall 诊断 AUC（0.763→0.763），OGTT RMSE 反而由 32.127 增至 32.542 mg/dL。
- 结构指标目前更适合作为特定观察窗的形变描述器，而非稳定个人表型或单项疾病指标。

指标卡校准研究 `experiment_20260807_1610.md` 已进一步冻结以下解释边界：卡片颜色只表示当前窗口相对内部参考带的位置，不代表正常/患病，也不直接改变顶部筛查分值；实验性 FINS 回归 R²≈0.01，只能作低效度研究回放。

### 2. 外部临床边界

ADA《Standards of Care in Diabetes—2026》明确指出，目前没有充分证据支持使用 CGM 筛查或诊断糖尿病前期/糖尿病。NIDDK 同样将 A1C、空腹血浆葡萄糖、OGTT 等血液检测列为诊断途径。

因此，本日志必须把网页结果写成“内部研究模型分值”，而不能写成患病概率、诊断结论或治疗建议。

## 二、旧功能问题

原“输出日志”存在以下问题：

1. 点击后直接复制，没有预览，用户无法在复制前检查内容。
2. 输出采用“高维情报、宿主、吞噬张量、暴力平账”等提示词式修辞，不适合作为研究记录或临床沟通材料。
3. 筛查结果、旧版 MRI、结构指标和极值提示混在一起，缺少证据层级。
4. 没有说明顶部筛查使用固定的全时段/推荐 Tau 路径，而指标卡会随时段、Tau 和平滑控件变化。
5. 没有结构化格式，无法稳定进入后续研究脚本或版本审计。
6. 只依赖 Clipboard API；在部分本地 `file://` 环境中可能因权限失败，且没有降级复制方案。
7. 没有明确说明是否包含原始序列、文件名或本地路径。

## 三、最终交互设计

侧栏入口改为“查看输出日志”，并标明三个能力：

- 预览审计摘要；
- 复制文本；
- 下载 JSON。

点击后打开带焦点管理的模态预览：

- 支持点击关闭、遮罩关闭和 Escape 关闭；
- 支持键盘 Enter/空格打开；
- 关闭后将焦点还给原入口；
- 文本复制优先使用 Clipboard API，失败时退回临时 textarea + `execCommand('copy')`；
- JSON 使用浏览器 Blob 在本地生成并下载，不上传任何数据。

## 四、文本日志结构

文本日志固定为七层：

1. **筛查输出**：研究筛查分层、内部模型分值、实际模型路径、治疗语境、夜间均糖、动力学输入和阈值。
2. **数据质量与分析语境**：观察范围、日历日数、原始记录、有效血糖点、夜间点、相点数、单位转换、Tau、嵌入维数、平滑和 RQA 递归率。
3. **解释性结构指标**：9 项卡片的值、窗口状态和当前解释；FINS 独立标记为低效度。
4. **当前窗口血糖范围**：最低值、中位数、最高值及中性范围提示。
5. **证据边界**：ADA CGM 边界、v8.4 内部验证限制、最新可靠性和增量价值结果、FINS 效度。
6. **后续核实**：根据研究分层给出克制的核实说明，并列出 A1C、FPG、75 g OGTT；不提供治疗调整指令。
7. **可复现性与隐私**：日志格式、工具版本、筛查版本、生成时间、导出范围和参考链接。

开头固定说明：该日志不是诊断书，模型分值不是患病概率，卡片颜色不是疾病标签。

## 五、JSON 审计格式

新增格式版本：`glucobench.audit-log.v1`。

主要对象包括：

- `screening`：分层、模型分值语义、模型路径、阈值、内部验证摘要和实际输入；
- `data_quality`：观察范围、有效点数、重构参数、当前指标窗口和固定筛查输入范围；
- `metrics`：9 项指标的稳定 ID、显示名、值、状态和解释；
- `range_summary`：当前窗口极值与中性提示；
- `legacy`：旧版兼容分及其非筛查角色；
- `evidence_limits`：内部研究和外部指南边界；
- `clinical_boundary`：非诊断状态、核实路径和标准实验室项目；
- `privacy`：明确记录原始序列、文件名和本地路径均未导出；
- `references`：ADA 2026 与 NIDDK 官方页面。

默认 JSON 不包含：

- 原始血糖序列；
- 上传文件名；
- 本地文件路径。

## 六、范围提示校准

原日志中的“重度底盘击穿、糖毒性极值、安全结界”等表达改为中性观测，例如：

- “检测到低于 3.9 mmol/L 的读数”；
- “检测到高于 11.1 mmol/L 的读数”；
- “当前窗口未触发预设极值提示；这不等同于排除异常”。

旧版累计分的内部计算保持兼容，但日志明确说明该分数未经独立验证且不参与顶部筛查分值。

## 七、关键实现逻辑

1. `renderMetrics()` 在完成卡片渲染后构造统一的 `lastReportJSON`。
2. `buildAuditText()` 只从该 JSON 生成文本，避免文本版与机器版内容漂移。
3. 固定筛查路径和可变指标窗口分别记录：
   - 顶部筛查固定使用文件载入后的全天、EMA 开启、推荐 Tau 路径；
   - 时段、Tau、平滑控件只改变图和解释卡。
4. 模态框打开时若用户重新分析，预览会自动按当前参数刷新。
5. 工具界面版本升级为 v8.4.2，筛查逻辑版本仍为 v8.4。

## 九、后续建议

1. 在获得允许的本地 HTTP 预览环境后补做窄屏与长报告滚动的像素级检查。
2. 若将来需要跨版本批量分析，保持 `glucobench.audit-log.v1` 字段向后兼容；破坏性修改应升级 schema 版本。
3. 可增加用户主动选择的“匿名研究编号”，但默认仍不导出文件名或路径。
4. 若未来模型通过独立外部验证，应新增独立的验证来源字段，而不是改写历史日志中的证据等级。
